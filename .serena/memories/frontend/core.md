# Frontend (`apps/frontend`)

- Vite 8 + React 19 + TypeScript 7; `tsc -b` project references. `src/App.tsx` renders the Secret Tinder overview with a read-only public proof section. `src/pages/Participation.tsx` dynamically loads `participation-verifier.ts` on user action, so ENSv2 Sepolia and Arkiv Rabdi reads do not use the Hono backend. Alice/Bob browser results matched `scripts/verify-participation.ts` at each identical Sepolia block; see `specs/001-private-dating/evidence/ens.md`.
- `vite.config.ts` enables Void and React, plus vite-plugin-pwa except when `VERCEL_STATIC_BUILD=1`. `void.config.ts` configures the Worker compatibility date; `apps/frontend/AGENTS.md` points to installed `void/docs/` (quickstart and CLI).
- Do not assume static-SPA-only architecture: build emits a Worker and assets under `.cloudflare/output/v0/workers/default/`, plus the static client in `dist/client/`. Clean local builds logged PWA service worker generation but did not retain `sw.js`; Vercel build disables PWA and serves `dist/client` via `apps/frontend/vercel.json`. Current Turbo output globs omit .cloudflare/output.
- Backend remains a separate Hono Worker template. Void presence does not establish product API integration; use the specification's service ownership and API contract before implementing.
- Styling dependency: lism-css. The current UI was checked under `.lism/plan.md` and `.lism/review.md`; use lism-css-guide for implementation, lism-mockup-guide for mockups, lism-css-refactor only when requested, and React guidance via vercel-react-best-practices and vercel-composition-patterns.
- Lint: oxlint, plus root Biome checks. Scripts: dev, build, lint, preview; no test script yet.
- API calls must follow packages/api-specs/openapi.yaml once populated; existing HTTP design is in specs/001-private-dating/contracts/service.md.
