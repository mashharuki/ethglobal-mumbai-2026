# ENS/Arkiv participation implementation

- Source map: `apps/backend/src/participation/ens-plan.ts` prepares ENSv2 Sepolia proxy/register/grant calldata; `issuer.ts` verifies a registration receipt and issuance generation; `publication.ts` prepares/validates signed public Arkiv entities. Shared trust/schema/EIP-712 code is in `packages/shared/src/participation/`. `scripts/plan-participation.ts` and `scripts/issue-participation.ts` are read-only CLIs; the latter emits an **unsigned** credential draft.
- Public chain evidence and current milestone status: `specs/001-private-dating/evidence/ens.md`; pinned trust input `ens-trust.json`, same-block snapshot `ens-onchain-snapshot.json`, signed Alice/Bob credentials, Arkiv publication proofs, and ENS reference proofs are in the evidence directory. Historical `specs/001-private-dating/fixtures/participation.json` records an earlier block when the parent had no subregistry; do not treat its zero address as current state. Recheck chain state before every send/verification.
- Chain split: ENSv2 on Sepolia chain 11155111; Arkiv SDK 1.0.1 targets Rabdi chain 7794095. The Arkiv access key and signer funding are separate from ENS. Never put keys in chat, evidence, browser bundles or committed files. SDK source/declarations and `arkiv`, `arkiv-first-write`, `arkiv-write-safety`, `arkiv-security-trust` guide funded writes.
- Alice/Bob EIP-712 credentials are signed, written to Arkiv Rabdi, and read back; Sepolia `app.credential` references are also written and read back. `apps/backend/scripts/verify-publication.ts` and `verify-reference.ts` check the receipts, approved calldata, and current public state. T038 remains open for finite suspension, delegated-key revocation, contract permission tests, and real participant-signed limited-key updates. T039 requires independent Web/CLI verification. Permission readbacks and `eth_call` simulations are not actual participant-signed writes. `tasks.md` and `contracts/participation.md` retain exact gates.
- Resolver access is keyed by `keccak256(bytes(textKey))`; participants use separate Resolver proxies so an `app.endpoint` role on one cannot edit the other. The issuer retains parent/Registry control and each Resolver root `ROLE_SET_TEXT`; verifiers must check current chain provenance and the signed reference, not owner alone.
