# ブラウザー、API、外部サービスの契約

この文書は実装前の設計である。HTTP の機械可読な契約は [packages/api-specs/openapi.yaml](../../../packages/api-specs/openapi.yaml) に集約し、実装時はそこで入出力と失敗コードを確定してからクライアントを生成する。公開登録、検索中の照合、任意のAIBot会話は公開範囲が異なる。

最初に実証する参加資格のschema・発行・独立検証は[参加資格契約](participation.md)を正本とする。資格読取はBFFの認可応答に依存させず、入金不要の検証画面と製品検索の許可を分ける。

## 用途別の境界

| 境界 | 渡してよいもの | 検証と保持 |
| --- | --- | --- |
| 独立クライアント → ENS / Arkiv | 仮名、信頼する発行者・Registry、公開資格参照 | 発行者署名・世代・現行版・状態・期限を自前で検証。私的プロフィールや既存BFFの成功フラグを入力にしない |
| 端末 → 公開登録 | 仮名、登録版、乱数で秘匿した登録コミットメント、登録証明、所有者の登録署名 | 仮名の管理権、現行版、登録証明を確認。職業・年齢帯の値、趣味と照合の送り先は公開しない |
| 端末 ↔ 照合相手 | 検索ごとの一時鍵、双方の登録版を拘束した秘匿照合のメッセージ | 相手の一時鍵と登録所有者の署名を照合してから暗号化チャネルを確立。相性の結果は各端末で検証し、中継先に平文の結果や共有した趣味を送らない |
| 端末 → AIBot | 本人引継ぎassertion、認可されたmatch / Persona、別同意のインタビュー・自由会話 | 非公開。公開台帳・URL・診断ログへ本人引継ぎや会話を出さない。Cookieと所有者認証はAIBotが担当 |
| AIBot → 推論提供者 | 送信承認済みインタビュー、承認済みPersona、場面、会話メモリー、本人の発話 | 同意画面で送信先と範囲を明示。照合用の秘密属性・希望・資金noteを自動転送しない。保存時暗号化と推論先への共有を区別 |
| 登録・精算 → 表示 | 確認済み記録と保留中の操作ID、元の銘柄・数量 | 最終的な預託・返却・受領の根拠はチェーン。APIの応答とモデルの出力に資金を動かす権限はない |

## HTTP と中継の操作（接頭辞 /v1）

ブラウザーは同一オリジンの BFF を利用する。ウォレット署名を使う認証では domain、URI、chainId、単回 nonce、有効期限を検証し、短命の HttpOnly/Secure/SameSite セッションを発行する。書込みでは Origin も確認する。資格は権限ごとに分け、公開データの読取をログイン必須にしない。[Sign-In with Ethereum](https://eips.ethereum.org/EIPS/eip-4361)

| 操作 | 要求 → 応答 | 必須の判定 |
| --- | --- | --- |
| POST /auth/challenges、POST /auth/sessions | address → 期限付き署名文。message、signature → セッション | nonce の原子的消費。署名と登録・精算への同意を分離 |
| POST /registrations | alias、version、commitment、proof、ownerSignature、depositRef → 202 と operationId | 認証所有者、登録署名、預託所有者と confirmed 状態、検証鍵・公開入力を照合。期限切れ・旧版を拒否 |
| GET /operations/{id}、GET /registrations/{alias} | 本人操作 → pending / confirmed / failed。公開仮名 → 現行公開登録または404 | 登録照会では ENSv2 で解決した現行の登録参照と Arkiv の実データを比較。ペアを返す項目は持たない |
| POST /search-leases、PATCH /search-leases/{id}、DELETE /search-leases/{id} | 一時公開鍵・資格世代/版・登録版・本人署名 → leaseId、expiresAt。更新・退出 | 有効資格・確定預託・現行登録を開始/更新時に検証。30秒リースを10秒ごとに更新する初期設定。明示退出、接続検知、期限で失効。希望条件を平文で受け取らない |
| GET /search-leases/{id}/channel（WebSocket） | 認証済みリース → roundId、assignmentId、一時ランデブー、順序付き暗号文 | 割当は相性成立ではない。各人K/同時数を検証し、切断で未完了照合を破棄。候補確定前に両端末も双方の現行資格・登録・リースを再検証。中継ログに本文・相性結果を残さない |
| POST /invites、POST /invites/{id}/decisions | 登録版・預託・最短期限への当事者署名を封入した暗号文と、下記の認証用封筒 → 招待ID・配送状況。双方承諾後は署名付き受付証 | APIは封筒の同一操作への双方承諾と現行資格を照合する。当事者が復号して資金署名を検証し、両預託の拘束確定後だけ成立と表示してマッチ参加資格を発行する。失敗・競合は不成立、成否不明は確認中として同じ操作を再照会する |
| POST /simulation/identity、GET /matches/{matchId}、POST /date-requests | [AIBot契約](simulation.md)の本人assertion、サービス認証付きマッチ照会、冪等申請 | 認証subject・相手Persona・拘束成立・現行同意・ブロック・期限を照合。ゲームはAIBotが管理。申請送信だけではacceptedにしない |
| GET /deposits/{id} | 所有者 → 公開入金のasset、数量、確認状態。非公開の受取権・受取済み量は端末で復元 | 銘柄は[許可リスト](settlement.md)の chainId + token address の組（USDC・EURCのみ）、数量は最小単位の10進文字列。秘密の権利と公開receiptから端末で復元し、期日到来時の返却をモデル・API障害中にも実行できる |

状態を変える POST/PATCH は同一主体・操作ID・同一内容の再送に同じ受付結果を返す。同じキーで異なる内容、旧版、状態違いは409。未認証は401、他人の非公開リソースや不明IDは404、無効な値は422、検索頻度/同時数超過は429、外部サービス停止は503。送信後の確認待ちは202として既存操作を照会する。機密値・署名・権限URLをエラー、テレメトリー、PWAの共有キャッシュに残さない。

本人の新規検索に対する資格無効は403、資格の現行状態を取得できない場合は503とし、古い成功結果で許可しない。これらを既存預託の取消・期限返却・受領の条件には使用しない。

認証用封筒は招待ID、当事者のリース参照、operationId、chainId、資金契約、拘束入力digest、承諾期限、主体署名を持つ。各端末の承諾は同じdigest・期限・相手のリースへ拘束する。署名受付証の形式と信頼する受付公開鍵/版はT003/T005で固定し、回路・契約の設定へ拘束する。要求が指定した任意の鍵は信頼しない。MVPの鍵変更は新しい検証設定として扱い、既存資金の返却には影響させない。封筒と受付証は当事者専用であり、APIがペアのメタデータを知る制約は残る。

双方承諾時、調整用APIは両者の現行資格・登録・リースを確認し、特定の拘束操作を受付ID・入力digest・受付有効期限へ固定して署名した受付証を返す。期限は両者の承諾期限・両リース・両預託期限の最短以下。同一operationId/digestの再送は同じ受付証を返し、有効期限を延ばさない。暗号化された対人内容を復号せず、認証済み両者の同じ操作への承諾を照合する。「送信済み」という自己申告は境界に使わない。

停止前に受け付けた同一操作が受付期限内に拘束確定した場合だけ、停止後も既存マッチとして成立させる。停止後の新規受付・digest差替え・期限切れは拒否する。資金契約はENSを再読取せず、受付署名と期限を検証するため、APIへの受付権限の信頼は残る。返却操作にはこの受付証を要求しない。T016で受付前/後/期限切れを検証する。

## 参加状態と救済の私的API

[資格審査契約](participation-review.md)を入力に、以下もOpenAPIへ定義する。本人認証と新規検索資格を分け、停止中も本人のケース・反証・異議・返却復元を認可する。MVPで受け付ける証拠は合成fixtureIdのみで、実在者の自由記述や画像を保存しない。

| 操作 | 要求/応答 | 認可と効果 |
| --- | --- | --- |
| POST /review-cases | 合成接触資格、fixtureId、policyVersion、操作ID → 私的caseId | 関係者本人のみ。重複を集約し、受付だけでは停止しない |
| GET /review-cases/{id} | 本人向け根拠/期限/状態、担当者向け合成材料 | 当事者・指定担当者のみ。他人は404。公開資格へcaseIdを出さない |
| POST /review-cases/{id}/responses、/appeals | 操作ID、expectedRevision、合成の反証/異議 → 更新状態 | 停止中も本人認証で利用可。無回答を同意にしない |
| POST /review-cases/{id}/decisions | 規則・判断・有限の停止期限・revision → 状態更新 | 指定担当者と利益相反を検証。一次/異議の担当を分離。資金操作は呼ばない |
| POST /blocks、DELETE /blocks/{id} | 本人が指定する相手 → 接触制限状態 | 他人の全体資格は変えず、本人との新規招待・対人通知・相手PersonaのAI利用を止める。救済/資金復元は維持 |

初回確認済みの利用枠は発行者の現行署名資格から読み、新規はround上限1、通常はK。停止は最新参照の集約期限で判断し、ブロックしたペアを新しい割当から除く。SC-006のN負荷fixtureは通常枠で固定し、新規枠とブロック除外はT040/T016の追加例で確認する。段階AのSC-007は署名付きtier更新・枠の判定fixture・私的ブロック状態の保存までとし、実際の割当を要求しない。

## 多人数の割当と保持（段階C）

- ラウンドは調整用DOが管理する30秒単位の初期設定。K=3、同時実行=1を合成試験の初期値とし、クライアント操作でroundや上限をリセットさせない。
- 長く待つ参加者から選び、同順位はランダムにする。自分自身、同一資格主体、既に照合した同一ペア/登録版、失効リース、上限到達者を除外する。二人の予算と同時枠を原子的に確保してからassignmentを発行する。
- 中断も割当予算を消費し、通信再送は同じassignmentに戻す。拒否・切断だけで金銭的罰則や資格停止を行わない。単一参加者による大量リースを認めない。
- リース終了時に保留暗号文は削除する。再接続での探索制限回避を防ぐため、ペア/版の実施済み印と予算は本文・属性・相性結果なしで保持し、対象登録の有効期限と両預託期限の最短まで、最長7日で削除する。運営がペアの通信メタデータを知る制約は残る。
- SC-006では各人の待機・割当数、上限違反、再送、切断復帰を記録する。全候補を調べ切ることや特定時間内のマッチは保証しない。枠待ち・未照合を不一致と表示しない。

## 整合性と統合確認

- **検索・招待**。実証用には一つの調整用 Durable Object がリースと暗号文配送を直列化する。二重引当の最終判定は精算契約が行う。反映が不明なら端末は確認中を維持して受領記録を照合する。本人同意がない相手を候補に挿入できないことは、クライアント側でも登録版・検索セッションへの拘束を検証する。
- **AIBot**。[接続契約](simulation.md)の署名付き本人引継ぎ・サービス認証・subject/Persona対応・現行同意・冪等申請を親APIへ定義する。AIBotの既存ゲーム管理を再利用し、旧DO部屋/共同手番は実装しない。デモマッチと実AIの有無を別表示し、外部推論の送信同意を確認する。
- **ENSv2**。T037〜T039で[参加資格契約](participation.md)の権限分離と独立検証を先に実装する。本人が資格参照を更新できる構成にしない。T014で現行資格をプロフィール登録・預託に結合する。所有権と更新権、名前期限と資格期限、参加資格とAI利用認可を区別する。[現行公式索引](https://docs.ens.domains/llms.txt)
- **Arkiv**。Rabdi（7794095）に公開登録だけを書く。レコードは許可された発行者の readonly 登録版と所有者署名を検査し、ENS の参照・版が一致する現行データだけを表示する。期限切れは公開確認不能と表示する。読み込み不能と「登録なし」を区別する。アクセスキー付きRPC URL はサーバー側に置く。実際の書込み元アドレス・再現可能な読取クエリ・画面結果を賞の応募証拠にする。[Arkiv公式](https://docs.arkiv.network/)・[Mumbai審査条件](https://ethglobal.com/events/mumbai/prizes/arkiv)
- **Kohaku / Anon RPC**。PWAでウォレット接続・ネットワーク切替を確認し、ENS解決・預託残高などアプリ自身のSepolia読取を、実際に匿名化するトランスポートに既定で渡す。起動時の参照・ウォレットの送信・Arkiv読取の通信経路をREADMEで区別する。匿名経路が停止した場合はその状態を表示して再試行させ、端末テストでは通常RPCへの暗黙の切替が生じていないことを観測する。[Anon RPC公式](https://ethereum.github.io/anon-rpc/wallets/)・[Kohaku](https://github.com/ethereum/kohaku)
