# 計画への引継ぎ

[利用者向けの仕様](spec.md)に対応する技術指定を保存する。以下は計画時の入力であり、統合の実現性・対応バージョンの検証は計画段階で行う。

| 担当範囲 | 指定された技術・構成 | 主な仕様との対応 |
| --- | --- | --- |
| フロントエンド | React、Vite、VoidZero、TypeScript、lism CSS、PWA、Kohaku、Anon RPC。仮名はENS V2サブドメイン、ZK証明は端末で生成 | 登録・ウォレット・公開範囲の説明・相性確認・二人の手番・精算内容の確認 |
| バックエンド | Cloudflare Workers、Wrangler、Hono、Zod、OpenAPI、OpenAPI Generator。秘匿した入力を含まない記録はArkivを利用。World Modelは場面と次の状況を生成 | 証明と候補、共同セッション、再開、場面生成に渡す情報の境界 |
| スマートコントラクト | Ethereum Sepolia、Hardhat V3、Solidity | 登録時の預託、マッチへの引当、双方の確認、期限後の返却、同じ銘柄での90/10精算 |
| リポジトリ共通 | pnpm、Turborepo、TypeScript、Biome、jscpd、knip、GitHub Spec Kit | モノレポで3領域の計画・検証を分担 |
| ゼロ知識証明 | 回路の記述には **Noir** を採用する。ブラウザー上の入力処理にはNoirJS、証明生成・検証にはBarretenbergを候補とし、動作確認した組み合わせを固定する | 公開の登録証明（FR-002）、二人の非公開照合（FR-004、SC-002）、対面提示時の登録版の確認（FR-008） |

[提供された構成図](../../docs/architechture.drawio.png)では、端末がウォレット・デーティング画面・証明生成を担い、World Modelが場面を返す。バックエンドとモデルの接続方法、異なる銘柄の移転特性、公開識別子間の関連付けは設計段階の検証対象とする。

## Noirで証明する範囲

- **登録**では、仮名の所有者が、対象の登録版に結び付いた自己申告値を知っていることを示す。検証側は仮名の所有権と現行版も照合する。趣味・職業・年齢帯と推測防止用の乱数は端末に保持する。対面時に確認できるのは、本人が選んで示した値と登録版との一致まで。申告内容の現実の真偽と90/10の精算は、仕様どおり対面後の双方の判断に従う。
- **相性照合**では、二人がそれぞれ持つ秘密を一つの端末に集めるとFR-001を満たせない。二者が入力を秘密にしたまま「共通項が一つ以上ある」という真偽だけを得る方式と、各入力が登録版の許可済み趣味に由来することをNoirで結び付ける方法を、最初に検証する。ペア・双方の登録版・検索セッションを検証対象に含め、相性証明やペア識別子は公開しない。趣味を列挙して照合できる固定ハッシュも公開しない。
- **提出前の確認**では、2端末で共通趣味あり／なしを試し、別人・別版の証明再利用と片方の検索終了を含むSC-002の5例を確認する。実測した証明時間と各端末・運営・公開記録が取得できた情報を記録する。二者照合まで通らなければ、デモで実証できた登録証明と未検証の相性判定を明示する。[Noir公式ブラウザーガイド](https://noir-lang.org/docs/guides/building_a_web_app)
