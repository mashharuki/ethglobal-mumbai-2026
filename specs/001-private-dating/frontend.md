# フロントエンド仕様

参加者が非公開プロフィールを端末に保ち、検索、対面での選択開示、精算内容の確認を自分で操作できることを担当する。照合用Noir回路と端末間検証もこの領域で扱う。資金移動用の回路・検証条件は[スマートコントラクト仕様](smart-contract.md)、通信とAIBotへの認可は[バックエンド仕様](backend.md)を参照する。

[共通の利用シナリオと成功基準](spec.md)・[実装タスクと分担](tasks.md)

## この領域が主担当の機能要件

- **FR-001** 登録者は端末で趣味、自己申告の性別・交際目的、相手に希望する性別・交際目的（指定なしを含む）を入力し、照合への利用と公開範囲を確認できる。値と希望集合は登録版に固定し、API、ログ、公開記録、モデルへ平文で送らない。真偽と自分の希望から相手の属性を推測できる場合があることを説明する。
- **FR-004** 新規候補の照合は双方が有効な参加資格と現行登録を持ち、同時に検索している間だけ行う。双方の性別・交際目的の希望を互いの自己申告が満たし、許可済み趣味が一つ以上共通する場合だけ候補にする。指定なしは当該希望を制限しない。表示・プロトコル出力は条件全体の真偽と仮名までとし、条件別の成否、共通項・件数を返さない。証明は自己申告との整合性までで、現実の属性や交際成功を証明しない。
- **FR-008** 対面・継続・終了は本人の意思で決める。職業/年齢帯の選択提示は本人端末内で登録版との一致を確認する用途に限り、金銭罰則と結び付けない。合意終了時は各自に返る銘柄・元本と対象マッチを確認して署名し、合意がなくても固定期限に単独返却できることを示す。

- **FR-016** 本人は停止の根拠・期限・規則・異議申立ての手段を確認し、停止中でも反証・異議・資金復元を行える。本人のブロックは相手との新規接触を止めるが、既存の返却権を止めない。新規枠を低評価と表示せず、申告件数・人気・預託額の信用スコアを作らない。MVPの審査入力は合成ケースと明示する。

## 他領域との受け渡し

| 操作 | 端末で判定・表示すること | 担当間の引き渡し |
| --- | --- | --- |
| 参加資格の検証 | 発行者と本人の更新権を区別し、資格の有効・無効・確認不能を表示する。資格だけで検索可能と表示しない | 入金不要の先行実証と製品登録を区別。[参加資格契約](contracts/participation.md)を独立検証ツールと共通schemaで確認 |
| 登録・預託 | 秘密値と項目別の乱数を端末に保存し、預託銘柄はUSDCとEURCの二択とし、Ethereum Sepolia以外では預託操作を止める。公開予定の情報、選択した銘柄のアドレス、数量、期限の計算方法と分配を署名前に示す。入金後は確定期限を表示する | 公開登録証明と所有者署名をAPIへ渡す。確定入金後に登録が失敗したら、未拘束分の即時取消を案内する |
| 同時検索・招待 | 相性証明を双方の現行版・一時鍵・検索世代に照合する。真なら仮名と成立結果を出し、不一致、失効、再利用では候補を追加しない | バックエンドには暗号文を渡す。承諾した登録版・預託・期限と実際の拘束を照合し、確認中／成立／不成立を区別する |
| 任意のAI会話 | AI送信内容・相手Persona・実AI/定型デモ・架空/実マッチを区別してAIBotへ渡る。承認・校正・会話UIはAIBotを再利用 | 照合秘密を自動転送しない。現行同意、本人引継ぎ、別Origin、期限切れ、撤回を確認。申請送信を対面成立と表示しない |
| 提示・返却 | 選択した職業/年齢帯を本人端末だけで提示。合意終了・単独返却と各自の元本を確認して署名 | 元本・受領状態を秘密の権利と確定取引から復元。私的な申告・審査・本人ブロックは別の権限で扱い、署名/返却を妨げない |

## 独立して確認すること

- ENSの独立検証（SC-005）後、2台に別々の秘密を置き、SC-002の10例を実証明で試す。希望条件別の中間結果を返さず、入力・希望maskの改変も拒否する。各端末の時間・通信量を測り、実ウォレット・本番中継は後段で結合する。
- 初見の登録と承認済みPersonaとの会話・AI送信範囲の理解はSC-001・SC-003で評価する。職業だけを提示する例では年齢帯が映らないこと、送信内容・共有キャッシュに非公開値が残らないことを観察する。
- 署名直後、取引確認待ち、確定、失敗を切り替えて表示を確認する。拘束失敗では部屋への導線を開かず、成否不明では同じ取引を再照会する。

## 正式応募目標での責任

Web/ZK担当は[EF-CROPS](prize-targets.md)の主担当として、T035で2端末の実照合と第三者が得る情報を検証する。資金の公開範囲はT024、運営ログ・メタデータはAPI担当と照合し、CROPSの説明を実装に合わせる。Web担当はT008の標準読取について、追加応募EF-RPCの成否を別に記録する。

ENS-V2には先にT039の独立検証画面とツールを提供し、T034で権限分離・可搬性・失効を示す。T015は後段の製品登録画面としてARKIV-APPのT032にも証拠を渡す。実読取とfixture表示を区別し、最終判断はT036へ渡す。
