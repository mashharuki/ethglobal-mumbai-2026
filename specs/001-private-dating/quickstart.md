# 開発時の起動と受入確認

以下は実装担当が使う手順。現状はテンプレート段階で、プロダクトの成功例は受入目標を示す。

## ローカルの準備

Node 24・pnpm 11とロックファイルに合う依存を準備する。リポジトリルートから各アプリを別ターミナルで起動する。

~~~sh
pnpm install --frozen-lockfile
pnpm --filter frontend dev
pnpm --filter backend dev
pnpm --filter contract exec hardhat node
~~~

フロントが表示するURLを別ブラウザープロファイルのA・B・第三者Cで開く。実機でウォレット・Web暗号機能を使う際は各端末から到達できるHTTPSオリジンを用意する。Hardhatのローカル時刻操作はコントラクト試験で使用する。Sepolia、ENS親名、Arkiv書込、Anon RPC、モデル接続の認証情報は担当者が管理し、開発用設定の実値を共有記録に残さない。ローカルチェーンのテスト鍵をSepoliaで再利用しない。

Sepoliaでの資金試験では[Circle Testnet Faucet](https://faucet.circle.com/)でEthereum Sepoliaを選び、Aのテスト用ウォレットにUSDC、BにEURCを受け取る。ウォレットのネットワークと[許可アドレス](contracts/settlement.md)を確認し、送金手数料用のSepolia ETHも用意する。下表の100／40の配分例はローカルfixtureで再現できる。

## 15:00の先行実証

独立した2台に、それぞれ自分の架空登録版・テスト鍵だけを置く。テスト用の配送経路で暗号文を交換し、実回路で生成・検証する。一致と不一致を各1回以上再現し、検索終了後に候補が追加されないことを確かめる。端末・回路版、検索開始から結果表示までの実時間、各端末の証明生成・検証時間を記録する。実ウォレット・外部チェーン・本番中継を使う結合試験は次の段階で行う。

動画では同じ実行の開始と結果を通常速度で残し、証明生成・トランザクション確定の待機だけをカットする。字幕には未編集の計測記録から実測秒数を転記する。

## 再現用の組と期待結果

| 操作 | 観察する結果・証拠 |
| --- | --- |
| Aは趣味「映画・音楽」、Bは「音楽・料理」、Cは「登山」で架空登録し、USDCとEURCを準備。A/B同時検索→A/C同時検索→B退出で再検索 | A/Bだけが候補。Cは仮名の登録確認だけ可能。別版・別人・終了リースへの証明の再利用は失敗。通信記録、公開台帳、モデルリクエストで趣味の値・ペア一覧を検査（SC-002） |
| 未対応銘柄と、USDCを名乗る別アドレスを指定して預託を試す | 画面の選択肢はUSDCとEURCのみ。UIを経由しない入金も契約が拒否し、残高・預託記録は変化しない。APIもその入金では登録を認めない |
| 入金確定後に登録APIを失敗させ、再試行してから未拘束の預託を取り消す | 期限は入金ブロック時刻＋604800秒のまま。本人は期限前に全額回収できる。別の預託では期限ちょうどの拘束を拒否し、単独返却できる |
| 同じ預託に対する二つの承諾を同時送信。片方を再送しブラウザーを再読込 | 双方承諾だけでは確認中。拘束が確定した一件だけに部屋資格を発行し、失敗・競合した招待は不成立。確認中の操作は同じ受付状態に復帰。第三者がストレージ・calldata・イベントから仮名の組を直接抽出できない |
| Aは100 USDC、Bは40 EURC。Aの職業に関する双方の最終回答を確定 | Bに90 USDCと40 EURC、運営10 USDC。101原単位では91/10。対象項目・責任者の不一致、未対面、一方無回答では期限後に各自で元本を回収。期限ちょうどの没収・二重受領は失敗（SC-004） |
| 登録版で職業のみ対面提示し、年齢帯を非表示にする。端末内の値を一つ変えて検証 | 正常な項目だけ一致し、変更値は不一致。提示だけで没収は起きない |
| 二人の同意→雨で予定変更→Aが屋内を選択、Bが同意。二ターン目で再送・切断・復帰。別ランではモデルを停止し退出 | 二人の選択が次の場面に反映。世代は一度だけ進む。停止中でも対面判断や期限返却は可能。シミュレーションの再開は部屋資格で認可 |
| 初見5人の登録、初見5組の2ターンを計時 | 登録は送金確定待ちを除く5分以内、共同体験は3分以内について、各4人／4組以上が仕様どおり達成・説明できたか実数を残す（SC-001/003） |

受領証拠にはブロック・取引、回路鍵の版、端末別の所要時間、外部接続の有無を記録する。データは合成のみとし、生の登録値や秘密鍵を診断ログに出さない。失敗時は該当ゲートを未達として記録する。

## 実装後のチェック

~~~sh
pnpm exec biome ci .
pnpm --filter frontend lint
pnpm --filter frontend build
pnpm --filter backend exec wrangler deploy --dry-run --outdir=dist
pnpm --filter contract format:sol:check
pnpm --filter contract build
pnpm --filter contract test
~~~

回路追加後は各Nargoパッケージで `nargo check` と `nargo test` を実行し、固定した証明バックエンドで生成と検証も独立に試す。回路単体テストだけをブラウザー間の合格と数えない。
