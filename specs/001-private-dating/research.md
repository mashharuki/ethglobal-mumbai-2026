# 設計判断と実証の境界

2026-11-06。以下は実装のための選択と仮説。二者照合の安全性、端末性能、各テストネットの動作は未実測である。

| 論点 | 採る方針と理由 | 検討した代案・制約 |
| --- | --- | --- |
| 非公開の一致判定 | 趣味と双方の希望を固定長の積集合座標に符号化し、暗号化内積の非零だけを返す既存案を段階Bで検証。全座標が登録値・希望maskから導出されたことをNoirで拘束する。[実験契約](contracts/matching.md) | 8座標から合成fixtureの288座標へ増えるため未実測。通常のPSI/件数出力やUIでの隠蔽では要件を満たさない。悪意ある参加者向け2PCが代案。 |
| 信頼範囲 | ブラウザー内でNoirJSとBarretenbergを動かす。まず対応するコンパイラ・実行系の組を実機で動かし、バージョンと回路鍵を固定する | 公開の相性証明や外部への証明生成依頼は、ペアや秘密入力を境界外に出す。端末の侵害・当事者による自主開示は防御範囲外。 |
| 先行するENS資格 | 発行者だけが資格参照を更新し、本人は独立Resolverの限定キーを更新。Webと独立ツールがENS/Arkivを直接再検証する。[資格契約](contracts/participation.md) | 共有Resolverで同じキーの更新権を全員に配れない。単一BFFの2画面は独立検証でない。親・管理者を信頼するテスト発行であり、Sybil耐性や評判の真正性を保証しない。 |
| 多人数候補選択 | 待ち時間順＋同順位のランダム選択、各人K上限、同時数制限で二者照合を割り当てる。N=10/50の段階Cで測定する | 私的属性の平文索引や全組合せの探索は採用しない。1ラウンドのO(NKC)は最適マッチ/全候補発見を保証しない。 |
| 運営・外部モデル | 検索時だけ短命の中継を使う。相性結果は当事者間で暗号化する。モデルに渡すものは二人が共有したテーマ・場面・選択だけ。参加者識別子と資金情報は除く | モデルが相性を推定する方式は検証可能な判定にならない。推論が止まってもペアは退出・対面判断・精算へ進める。 |
| 資金とプライバシー | テストネットで各人の預託を別の秘密の権利として扱い、公開書込みの入力から仮名や資金の相手を直接列挙できない設計を先に試験する。[精算契約](contracts/settlement.md) | 二つの公開ENS名や預託IDを一緒に記録する通常のマッチ台帳は不採用。金額・時刻・送金元の相関は残り、完全な匿名性を主張しない。 |
| 多銘柄 | Circleのファウセットで取得できるSepoliaのUSDC・EURCに絞り、原単位・原銘柄で会計する。価格オラクルや銘柄間の換算は不要 | 任意のアドレスが本当にステーブルコインかは判定できない。手数料・リベース・凍結・虚偽の残高応答を持つ資産で額面どおりの受取を保証できない。アドレス指定の自由入力は対象外とし、公式の2銘柄を許可リストで検証する。 |
| 正式応募目標と締切 | EF-CROPS・ENS-V2・ARKIV-APPを正式目標に固定し、P1の実証と3目標の証拠・提出物をP2の追加より優先する。T036で各賞を個別判定する | 正式目標であっても未達を応募完了にしない。模擬照合や既存Counterは完成証拠に使わず、公開スターター・OSS・新作・AI支援を区別する。EF-RPCは同じEF枠の追加判定とする。 |

暗号化された集合計算の背景は[Private Collection Matching Protocols](https://petsymposium.org/2023/files/papers/issue3/popets-2023-0091.pdf)、ローカル証明の実行経路は[Noirのブラウザーガイド](https://noir-lang.org/docs/guides/building_a_web_app)、曲線演算の実装可否は[Noir公式の演算リファレンス](https://noir-lang.org/docs/libraries/standard_library/cryptographic_primitives/embedded_curve_ops)で確認する。文献は以下の組み合わせ全体の監査結果を意味しない。大会・スポンサーの公式条件は[正式応募目標と提出判定](prize-targets.md)を参照。

## 2026-11-06 ブース後の決定

- Decision：ENS権限分離と独立検証 → 希望条件付き二者照合 → 多人数候補選択を採用。第一段階はZK・入金の実装を待たない。
- Rationale：スポンサー機能が製品で担う役割を先に実証し、その資格を検索へ結合する。私的条件の照合と人数への拡張を混同しない。
- Alternatives：名前の表示だけ、普通のPSI、全員の共通集合、多数の新規レイヤー仕様への分割は採らない。既存001とタスクIDを維持する。
- 暗号ライブラリの採用は未決定。[VOLE-PSI](https://eprint.iacr.org/2021/266)のCircuit-PSI拡張はsemi-honest設定で、現在求める悪意ある入力の検証をそのまま満たさない。[著者実装](https://github.com/ladnir/volepsi)のブラウザ適合性も未評価。現行案も合成プロトコルとして未監査で、T012の技術ゲートを省略しない。
- 追加決定：参加状態・利用枠・審査を分離し、根拠通知、有限の停止、異議・回復を合成ケースで実装する。マッチ預託は元本返却専用にし、旧90/10と運営の罰金収入を廃止。独立保証金と新たな没収は別実験の候補で、今回の実装対象外。預託それ自体が誠実さを証明するとは説明せず、利用者価値は引き続き検証する。
